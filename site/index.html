One real problem, one controlled path

Keep the work. Free the internal drive.

A full internal disk makes local AI development uncomfortable. A quick file move can make it worse if a live database is copied or the app starts without its SSD. Here is the sequence we use instead.

01 / BACK UPProtect what Git cannot.

Save conversations, credentials and databases independently. Preserve unpushed commits, untracked files and stopped container state.

02 / MOVECopy after writers stop.

Copy Codex and VM data to a correctly identified, encrypted SSD. Verify content, ownership, ACLs and usable worktrees.

03 / PROVEOpen it, then clean up.

Verify the real GUI, login, models and existing sessions, plus Docker health. Keep internal originals until the owner accepts the result.
